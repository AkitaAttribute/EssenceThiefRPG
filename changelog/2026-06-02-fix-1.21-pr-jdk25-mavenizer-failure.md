# 2026-06-02 Fix 1.21 PR JDK 25 Mavenizer Failure

## Prompt Provided

```text
The PR build failed but the branch did not. And only on the 1.21 build. This seems like a real error too.
```

## Build Failure

```text
Process 'command '/usr/lib/jvm/temurin-25-jdk-amd64/bin/java'' finished with non-zero exit value 1
```

The failure occurred during ForgeGradle/Minecraft Mavenizer setup while it was recompiling Forge/Minecraft sources, before this mod's source code compilation step.

## Cause

The 1.21.11 GitHub Actions matrix installed both Java 21 and Java 25 and also passed both installations to Gradle:

```yaml
java: |-
  21
  25
gradle_args: '-Dorg.gradle.java.installations.paths=${JAVA_HOME_21_X64},${JAVA_HOME_25_X64}'
```

The failed PR run selected Temurin 25 for the Forge Mavenizer/recompile path. Forge 1.21.11 is configured for Java 21 in the variant build file, and the Mavenizer source-recompile step should not be allowed to drift to Java 25.

## Proposed Solution Implemented

- Changed the 1.21.11 GitHub Actions matrix entry to install Java 21 only.
- Removed the `org.gradle.java.installations.paths` argument that exposed Java 25 to Gradle.
- Kept the 1.21.11 variant Gradle toolchain at Java 21.
- Left the 1.20.1 build on Java 17.
- Bumped `mod_version` to `0.2.12` in both Gradle property files.

## Files Changed

```text
.github/workflows/build.yml
gradle.properties
variants/forge-1.21.11/gradle.properties
```

## Updated Workflow Structure

```text
.github/workflows/build.yml
├── {build matrix minecraft-1.20.1 uses java 17}
└── {build matrix minecraft-1.21.11 uses java 21 only}
```

## Notes

This is a workflow/toolchain fix rather than a mod source-code fix. The mod code did not reach compilation in the failed PR run; the failure occurred during Forge/Minecraft dependency processing under Java 25.
