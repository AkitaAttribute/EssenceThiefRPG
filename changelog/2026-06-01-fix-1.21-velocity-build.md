# 2026-06-01 Fix 1.21 Velocity Particle Build

## Prompt Provided

```text
You broke the 1.21 build again.
```

## Build Failure

```text
variants/forge-1.21.11/src/main/java/com/akitaattribute/essencethief/client/particle/EssenceRisingParticle.java:8: error: cannot find symbol
import net.minecraft.client.particle.TextureSheetParticle;

variants/forge-1.21.11/src/main/java/com/akitaattribute/essencethief/particle/EssenceRisingParticleOptions.java:23: error: cannot find symbol
public static final Deserializer<EssenceRisingParticleOptions> DESERIALIZER = new Deserializer<>() {
```

## Cause

The velocity-particle patch copied 1.20-era custom particle implementation details into the 1.21.11 variant. The 1.21.11 Forge toolchain used by the GitHub Actions build does not expose the same `TextureSheetParticle` and `ParticleOptions.Deserializer` symbols under those names/APIs.

## Proposed Solution Implemented

- Changed only the 1.21.11 variant's trail particle implementation.
- Removed the custom 1.21.11 particle classes that failed compilation.
- Removed custom 1.21.11 particle registration and client particle provider registration.
- Switched the 1.21.11 trail to vanilla `ColorParticleOption.create(ParticleTypes.ENTITY_EFFECT, red, green, blue)`.
- Kept velocity-based spawning through `ServerLevel#sendParticles` with `count = 0`, preserving the directional/velocity particle path instead of returning to server-side position tracking.
- Left the 1.20.x root custom particle implementation in place.
- Bumped `mod_version` to `0.2.5`.
