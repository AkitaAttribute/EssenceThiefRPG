```

variants/forge-1.21.11/src/main/java/com/akitaattribute/essencethief/particle/EssenceRisingParticleOptions.java:23: error: cannot find symbol
public static final Deserializer<EssenceRisingParticleOptions> DESERIALIZER = new Deserializer<>() {
```

## Cause

The previous 1.21.x buildfix removed the custom particle files from the zip, but that does not delete stale files from an existing Git checkout if the zip contents are copied over the repository. The GitHub Actions failure still compiled the old custom 1.21 particle files, so those stale files were still present in the working tree.

## Proposed Solution Implemented

- Kept the 1.21.x trail implementation on vanilla `ColorParticleOption` with `ParticleTypes.ENTITY_EFFECT`.
- Added compile-safe 1.21.x compatibility placeholders at the old custom particle paths so stale checkouts are overwritten instead of left behind.
- The compatibility placeholders do not register or drive custom particles.
- `EntityTrailManager` remains the actual 1.21.x velocity-based trail implementation.
- Bumped `mod_version` to `0.2.6` in both Gradle property files.
